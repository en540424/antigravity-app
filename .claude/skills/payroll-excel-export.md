# Skill: payroll-excel-export（ExcelJS出力の安全手順）

## 目的
給与台帳/帳票のExcelJS出力を「最小変更・壊さない」手順で修正する。
列幅・結合・罫線・数式・テンプレ複製の崩れを防ぐ。

---

## 事前確認（必須）
- どの帳票か（ファイル名/テンプレ名）
- どの出力APIか（route.ts / server action 等の入口）
- 変更対象が「テンプレ」か「出力ロジック」か

---

## 影響範囲の列挙（必須）
以下を必ず書き出してから着手する：
- 触るファイル（最大3つ）
- 触る関数（例：clone処理、fill処理、数式上書き）
- 影響するシート名/セル範囲

---

## 絶対ルール
- テンプレ複製ロジックは“意図なく変更しない”
- 列幅/行高/結合/スタイル/数式の順序を崩さない
- 変更は1テーマずつ（例：結合だけ、数式だけ）
- diff提示→確認→適用（推測実装禁止）

---

## 実装手順（固定）
1) 現状の期待値を明文化（「何が崩れているか」を箇条書き）
2) 再現手順を作る（入力データ最小で）
3) 変更箇所を最小に絞る（1〜2関数）
4) diffを提示（貼り付け可能）
5) 出力確認（最低限）
   - 生成ファイルを開いて、結合/列幅/罫線/数式の崩れチェック
   - 2人目以降のシート（複製後）も必ず確認

---

## 確認コマンド
- `git status`
- `npm run lint`（ある場合）
- `npm run dev` で出力実行（該当API叩く/画面操作）
- 生成Excelの目視確認（1人目/2人目）

---

## よくある事故と対策
- 末尾改行やフォーマット変更だけで差分が汚れる → 変更範囲を限定
- 1人目OKで2人目崩れる → “複製元が汚れていないか”を必ず確認
- 数式上書きでテンプレが壊れる → baseWb/outWbを分離して扱う
